# B200 SOL, VSA, and PR #18329 performance comparison

Date: 2026-09-02 UTC

## Summary

This report separates three different questions that should not be mixed:

1. How the current two-stage SOL and VSA integrations perform in the same
   checkpoint-loaded Wan 14B transformer replay and prompt-derived pipeline.
2. How the current two-stage SOL compares with the fused SOL implementation in
   [TensorRT-LLM PR #18329](https://github.com/NVIDIA/TensorRT-LLM/pull/18329)
   in those same two workload envelopes.
3. Where the time goes inside a single SOL attention invocation.

At the target Wan 14B envelope, the current two-stage SOL has no observed
performance blocker relative to the draft fused implementation. The two are
effectively tied for a complete 40-layer transformer replay with deterministic
synthetic inputs, while the current path is about 3% faster in the matched,
prompt-derived four-step pipeline run. The direct
single-attention benchmark shows a shape-dependent crossover: PR #18329 wins
at `S=4096, H=8`, while the current implementation wins at the target
`S=10800, H=40` shape.

The current benchmark setting is `tau=1.0` with no dense prefix. This is useful
for implementation comparison, but it is not a calibrated production-quality
configuration. PR #18329 reports its quality-qualified points with `tau=2.0`
and a model-specific dense prefix; those published numbers are not directly
comparable with the runs below.

## SOL and VSA in the same Wan 14B workloads

All variants in this section were run sequentially on the same host with
`CUDA_VISIBLE_DEVICES=7`, the same checkpoint, seed, and CUDA-Graph policy. The
transformer replay uses fixed synthetic latent and text tensors; the complete
pipeline follows a real prompt/scheduler/VAE trajectory.

### Checkpoint-loaded 40-layer transformer replay

Input envelope: batch 1, latent `[1,16,3,90,160]`, post-patch sequence length
10,800, text `[1,512,4096]`, timestep 0.5. The latent and text tensors are
deterministic `torch.randn` inputs rather than prompt-derived activations.
Values are median CUDA-Graph replay latency over ten samples.

| Variant | Median latency | Relative to SOL | Peak allocated |
|---|---:|---:|---:|
| Dense SDPA | 370.786 ms | 1.053x slower | 28.448 GiB |
| SOL two-stage, PrimTS | **352.110 ms** | baseline | 29.301 GiB |
| VSA, PrimTS fine attention | 454.890 ms | 1.292x slower | 33.091 GiB |
| VSA, CuTeDSL fine attention | 536.673 ms | 1.524x slower | 32.903 GiB |

VSA PrimTS is 1.180x faster than VSA CuTeDSL for this transformer replay.

### Complete four-step VisualGen pipeline

Workload: 720x1280, 9 frames, 4 denoising steps, guidance scale 5.0. Values are
median wall-clock request latency after graph capture and one warmup request.

| Variant | Wall median | Denoise median | Frames/s | Relative to SOL |
|---|---:|---:|---:|---:|
| Dense SDPA | 3.4423 s | 3.1334 s | 2.6145 | 1.038x slower |
| SOL two-stage, PrimTS | **3.3162 s** | **3.0087 s** | **2.7139** | baseline |
| VSA, PrimTS fine attention | 4.3284 s | 4.0228 s | 2.0793 | 1.305x slower |
| VSA, CuTeDSL fine attention | 4.5679 s | 4.2629 s | 1.9703 | 1.377x slower |

VSA PrimTS is 1.055x faster than VSA CuTeDSL for the complete pipeline.

### Sparsity is not matched

- SOL uses `tau=1.0`. Its exact-route density across the 40 layers at timestep
  0.5 is 18.3369% mean, 18.1545% median, with a 17.3115%-22.9876% range.
- VSA uses `vsa_sparsity=0.875`; its requested fine-route density is 12.5%.
- VSA additionally performs coarse attention, learned gate prediction, top-K,
  padding/retiling, and coarse/fine combination. SOL performs summary/statistics
  prediction and one proxy-plus-exact block-sparse attention.

The SOL-versus-VSA table is therefore an end-to-end algorithm comparison, not
an equal-density FMHA comparison. It shows the cost of the complete current
implementations at this workload.

## Current two-stage SOL versus PR #18329 in matched Wan 14B workloads

PR #18329 was run through its public VisualGen API with the same Wan 14B
checkpoint and both workload envelopes. The transformer replay uses the same
seeded synthetic latent/text tensors on both paths. The complete pipeline uses
the same prompt, scheduler trajectory, and VAE. Both paths used `tau=1.0`,
diagonal thresholding, no dense prefix, BF16, and CUDA Graph. The matched pair
below was run sequentially on the same host with `CUDA_VISIBLE_DEVICES=1`.

### Checkpoint-loaded 40-layer transformer replay

| Implementation | Median [min, max] | Peak reserved | Backend evidence |
|---|---:|---:|---|
| Current predictor + PrimTS FMHA | 384.740 [364.972, 412.146] ms | 30.150 GiB | `SOLTrtllmAttention` |
| PR #18329 fused CuTeDSL SOL | 387.795 [372.761, 400.574] ms | 29.217 GiB | 40 `SolAttnAttention`, fallback 0 |

The current path is 0.79% lower by median, which is within the observed
system-noise range. The safe conclusion is that they are effectively tied for
the complete transformer workload.

Output comparison after all 40 layers:

- cosine: 0.9998718
- RMSE: 0.0050474
- MAE: 0.0039716
- max absolute difference: 0.0292969

### Complete four-step pipeline

| Implementation | Wall median [min, max] | Denoise median | Frames/s |
|---|---:|---:|---:|
| Current predictor + PrimTS FMHA | **3.2601 [3.2592, 3.2619] s** | **2.9558 s** | **2.7606** |
| PR #18329 fused CuTeDSL SOL | 3.3640 [3.3587, 3.6112] s | 3.0615 s | 2.6754 |

On the same visible device index, the current path has 3.09% lower median wall
latency and 3.45% lower median denoising latency. One PR sample was an outlier at
3.611 s; the median comparison is retained and the full range is reported.

Final decoded-video comparison between the two SOL implementations:

- cosine: 0.9919683
- RMSE: 15.8765 on uint8 RGB
- MAE: 8.8225
- max absolute difference: 255
- LPIPS Alex mean across all nine paired frames: approximately 0.1205
- maximum per-frame LPIPS: approximately 0.1471

Both paths are deterministic across graph replay (`max_abs=0`) and produce
finite outputs. Small per-layer BF16/routing differences accumulate over four
denoising steps; the decoded-video metrics are not a quality certification.

## Direct single-attention decomposition

This section uses the same saved random Gaussian Q/K/V tensors for both
implementations. The shapes are workload-representative, but the activations
are synthetic. Each pair was serialized on the same host with
`CUDA_VISIBLE_DEVICES=6` using seven CUDA-Graph timing rounds.

| Shape | Implementation | Predictor/preprocess | Attention core | E2E | Winner |
|---|---|---:|---:|---:|---|
| B1/S4096/H8/D128 | Current two-stage | 32.762 us | 46.486 us | 79.876 us | - |
| B1/S4096/H8/D128 | PR #18329 | 16.397 us | 53.478 us | **68.841 us** | PR 1.160x |
| B1/S10800/H40/D128 | Current two-stage | 247.972 us | 790.264 us | **1.0161 ms** | Current 1.142x |
| B1/S10800/H40/D128 | PR #18329 | 100.121 us | 1.0612 ms | 1.1604 ms | - |

The component columns are diagnostic, not independently comparable:

- The current predictor materializes the exact bitmap before the FMHA.
- PR #18329 preprocesses summaries/thresholds, while routing executes inside
  its fused attention core.
- E2E CUDA-Graph replay is the fair comparison.

At the target shape, the current predictor costs about 0.248 ms per layer. A
simple 40-layer sum is about 9.9 ms, or roughly 2.6% of the matched complete
transformer time. The faster current PrimTS proxy attention core offsets this
predictor cost.

### Direct numerical correspondence

| Shape | Exact density, current | Exact density, PR reconstructed | Route-bit agreement | Output cosine | Output RMSE |
|---|---:|---:|---:|---:|---:|
| S4096/H8 | 19.8059% | 19.8059% | 99.9329% | 0.9992513 | 0.0008108 |
| S10800/H40 | 17.3073% | 17.3104% | 99.9061% | 0.9988557 | 0.0006104 |

PR #18329 does not expose its internal fused route bitmap. Its route density
and agreement above are reconstructed from the PR preprocess outputs with the
documented selector formula; they are not a dump of the kernel's internal
route decisions. Reduction-order differences explain the small boundary-route
and output differences.

## Quality caveat

The `tau=1.0`, sparse-at-all-four-steps configuration is intentionally an
implementation/performance stress point. Against the current-branch dense
SDPA video anchor, LPIPS Alex is approximately 0.7597 for the current two-stage
path and 0.7627 for PR #18329. These values are not acceptable evidence for a
production quality claim.

PR #18329 documents quality-qualified model points using `tau=2.0` plus a
model-specific dense prefix. A production decision requires an equivalent
calibration sweep for the current two-stage path, evaluated against golden
videos with LPIPS and the project quality gates. The benchmark in this report
validates execution, determinism, implementation correspondence, and
performance; it does not approve a final sparse-quality operating point.

## Conclusions

1. Current two-stage SOL and PR #18329 fused SOL are in the same matched Wan 14B
   workload performance class at `tau=1.0`.
2. The current implementation is effectively tied for the 40-layer
   transformer and about 3% faster in the matched four-step pipeline run.
3. Direct attention performance crosses over by shape: PR wins the smaller
   S4096/H8 point; current wins the target S10800/H40 point.
4. The current predictor costs about 0.248 ms per layer at the target shape,
   but its faster PrimTS attention core offsets that cost.
5. SOL is materially faster than the current VSA implementations on this
   `S=10800` workload despite using a higher exact-route density. This is an
   algorithm-level result; VSA's coarse/gate/retiling overhead is included.
6. No safe backend-wrapper-only performance fix is evident. Further speedups require
   predictor, input-layout, or attention-kernel work.
7. Quality calibration remains required before treating either SOL path as a
   production operating point.
